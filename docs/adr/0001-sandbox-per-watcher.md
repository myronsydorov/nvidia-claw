# ADR-0001: One OpenShell sandbox per watcher

**Status:** Accepted (spike T-04 done on 2026-10-01: OpenShell 0.0.116, Docker driver, 4 vCPU / 8 GB DigitalOcean host)

## Context
Watchers are code written by the agent. We want per-watcher least privilege: a parcel watcher may reach the DHL API and nothing else. OpenShell identifies a process by the **real path of its executable** (with a recorded hash and process ancestry). So all Python scripts that share one interpreter look like the same program, and one sandbox can't give two scripts different network permissions.

## Decision
Each watcher runs in **its own OpenShell sandbox** with its own generated policy. Only `warden/src/warden/sandbox/` creates, applies policy to, execs in and deletes these sandboxes.

## Consequences
- ✅ Real isolation per watcher; a clear story for the video ("every worry gets its own jail"); denials are logged per watcher.
- ⚠️ A container per watcher costs startup time and memory. **The spike measures:** create time, exec time, memory per idle sandbox.
- **Fallback if it's too slow or heavy:** a pool of pre-warmed sandboxes (policy applied when a watcher is assigned), or start the sandbox per run and delete it afterwards.

## Spike results
`make spike` (`scripts/spike_sandbox.py`, through `warden.sandbox.openshell.OpenShellDriver`), one watcher using `weather_openmeteo` + `ics_calendar`:

| metric | value |
|---|---|
| create → Ready | **1.1 s** (`sandbox create --detach`, then poll `sandbox get -o json`) |
| policy set --wait | **8.2 s** (the sandbox picks policies up on a ~10 s poll; 9.1 s in a manual run) |
| upload run.py | 0.1 s |
| exec run.py | **0.12 s** for a no-network `emit`; 5.5 s for the probe below (5 HTTPS calls through the proxy) |
| delete | 0.3–0.4 s |
| RAM per idle sandbox | **12–14 MiB** (`docker stats`), with `--cpu 500m --memory 256Mi` limits |
| denied egress visible in logs | **yes**: `openshell logs <name>` shows OCSF lines, e.g. `NET:OPEN [MED] DENIED /usr/local/bin/python3.12(34) -> example.com:443 [policy:- engine:opa] [reason:endpoint example.com:443 is not allowed by any policy]` and `HTTP:GET [MED] DENIED GET http://api.open-meteo.com:443/v1/archive [policy:custody_api_open_meteo_com_443 engine:l7] … not permitted by policy` (they arrive ~10 s after the request) |

Probe results inside the sandbox: declared `GET api.open-meteo.com/v1/forecast` → 200; declared, percent-encoded Google Calendar ICS → 200; `example.com` → proxy 403; undeclared path `/v1/archive` → 403 naming the binary; `POST` to the declared path → 403; `%2F` in the path → connection dropped.

**Verdict:** one sandbox per watcher is cheap enough. ~10 s to stand one up (mostly waiting for the policy) and ~13 MiB idle means dozens of live watchers fit on this host; no pool is needed.

## What the spike pinned down
- **Policy schema** (OpenShell sandbox policy `version: 1`): a fixed baseline (`filesystem_policy` read-only `/usr /lib /proc /dev/urandom /etc`, read-write `/tmp /dev/null /sandbox /w`; `landlock: strict`; `process` as the `sandbox` user) plus one `network_policies` entry per host:port with `protocol: rest`, `enforcement: enforce`, `rules: [{allow: {method: GET, path}}]` and `binaries: [/usr/local/bin/python3.12]`. Generated by `warden/compiler/policy.py`; snapshots in `policies/examples/`.
- **Created network-less:** a sandbox is created with the baseline and an empty `network_policies`; the generated policy is applied with `policy set --wait` before any code is uploaded or run.
- **Filesystem can't be narrowed live** (`read_write path '/w' cannot be removed on a live sandbox`), and Landlock also binds `sandbox upload`. So `/w` (where `run.py` is uploaded) stays writable. Mitigation: the compiler's gate only lets generated code `open()` under `/tmp/`.
- **`sandbox exec` waits on stdin** unless it's closed; the driver always passes `/dev/null`. Exit codes, stdout and stderr pass through.
- **Approval mode stays `manual`** (the default): a sandbox can't get its own policy proposals auto-approved.
- **Image:** `watcher_runtime/image/Dockerfile` (python:3.12-slim + `iproute2` + the OpenShell `sandbox` user 998:998 + hash-pinned deps from `uv.lock`), built by `scripts/build-watcher-image.sh` into the local Docker daemon, tagged by content hash and `:latest`.

## Endpoint.path and percent-encoding (PLAN T-04 §§)
**How OpenShell matches** (measured with raw request targets): the L7 proxy *canonicalizes* the request path, then compares it literally with each rule's glob.
- An escape of a character that is legal in a path (unreserved, sub-delims, `:` and `@`) is **decoded**: `%40`→`@`, `%2B`→`+`, `%3A`→`:`, `%7E`→`~`, `%46`→`F`, and `%2A`→`*`.
- Every other escape **stays encoded**, in any hex case: `%23`, `%20`, `%25`, `%3F`.
- Dot segments are resolved (`/v1/x/../forecast` and `/v1/%2e%2e/v1/forecast` → `/v1/forecast`) and `//` is merged.
- `;params` are stripped before matching: `/v1/forecast;x=1` matched `/v1/forecast`.
- `%2F` (without `allow_encoded_slash`), `%00` and malformed escapes drop the connection.
- Paths are case-sensitive, and a trailing `/` is a different path.

So a rule written as `/a%40b` never matches anything, and a declared `*` would be a glob.

**Decision (safe rule):** `Endpoint.path` must be in OpenShell's canonical form, enforced by `adapters.base.canonical_path`.
- `parse_https_url` and the gate's URL check canonicalize worry-supplied URLs.
- Allowed literals: `A–Z a–z 0–9 - . _ ~ + = , : @ /`. Any other byte must be an upper-case `%XX` escape of a character OpenShell keeps encoded; non-ASCII becomes UTF-8 escapes.
- **Refused:**
  - `*` and `%2A` (globs);
  - `;` and `%3B` (path parameters, stripped before matching);
  - `! $ & ' ( )` (not needed, so they are kept out of the matcher);
  - `%2F`, control bytes and malformed escapes;
  - dot segments (`%2E%2E` included) and empty segments.
- The Google Calendar ICS link from T-09's `school_calendar` case now declares as `/calendar/ical/de.german%23holiday@group.v.calendar.google.com/public/basic.ics` and works live.
- **OpenShell limit, recorded:** because it strips `;params` and resolves dot segments before matching, the upstream server sees the raw path. A server that treats `;` or `..` differently from OpenShell could serve a sibling resource under an allowed rule. Every host is still only one the person approved, and GET-only.

## Private addresses (measured, T-04 security review)
OpenShell's SSRF engine always refuses a name that resolves to loopback or link-local, and logs it: `DENIED … -> 127.0.0.1.nip.io:443 [policy:- engine:ssrf] [reason:… resolves to always-blocked address 127.0.0.1]`, and the same for `169.254.169.254.nip.io`. Names resolving to RFC 1918 or Docker-bridge addresses (`10.19.0.5.nip.io`, `172.17.0.1.nip.io`) were **not** clearly refused: the requests timed out, and nothing was logged.
- **Decision:** the Warden resolves every endpoint host and refuses any non-global address (`compiler/hosts.py`). It checks before the dry run and again at approve, before a sandbox exists (`409`).
- **Port:** worry-supplied URLs must use port 443.
- **Still out of scope:** a name that changes its DNS answer after approve (rebinding), see THREAT_MODEL.

## Security review (T-04)
No invariant violations. Fixes applied, each with tests:
- The private-address check and the port-443 rule above.
- The `openshell` CLI gets an env allowlist, never the Warden's secrets.
- A policy read back from the database must be exactly what `generate_policy` makes: the baseline, `rest`/`enforce`, the one binary, and endpoints re-validated through `Endpoint`.
- Policy keys carry a host hash, so `a-b.x` and `a.b.x` can't merge.
- The scheduler re-uploads the approved `run.py` before every run, so a rewrite can't persist.
- `%5C` is refused in paths.
- The base image is pinned by digest, and the runtime is installed as a host-built wheel.
- Name and path checks use `fullmatch`.
- A failed `create` deletes whatever the CLI may have created.

**Follow-ups:**
- The watcher_runtime adapters' `fetch()` could also refuse `;`, dot segments and `%5C` in outgoing paths. A split-string URL can get past the gate's literal check, and OpenShell strips `;params`.
- Adapter secrets (`DHL_API_KEY`) still need an OpenShell provider attached at create (`--provider`); until then `parcel_dhl` watchers run without a key.
